# Kafka Partition Rebalancing Explained

Apache Kafka distributes data across brokers using partitions. When brokers are added, removed, or experience different loads, partitions can become imbalanced — leading to hotspots, performance degradation, and wasted resources.

## What Is Partition Imbalance?

A Kafka cluster becomes imbalanced when:

- **Leader imbalance** — Some brokers handle disproportionately more leader partitions
- **Replica imbalance** — Partition replicas aren't evenly distributed across brokers
- **Disk imbalance** — Broker disk utilization varies significantly
- **Network imbalance** — Some brokers produce/consume far more data than others

## Why Does It Happen?

Imbalance is natural and occurs during:

1. **Broker additions** — New brokers start empty while existing ones remain loaded
2. **Broker failures** — Partitions are reassigned away from failed brokers
3. **Topic creation** — Kafka's default placement isn't always optimal
4. **Uneven message rates** — Some partitions naturally receive more traffic
